# Deploy GymBro session persistence

This creates billable resources in your AWS account. Nothing is deployed by simply
running GymBro or its tests. The code/template are prepared locally; a deployed
cloud round trip is required before claiming that this component runs on AWS.

## Prerequisites

- AWS account and a chosen region, AWS CLI v2, AWS SAM CLI, Docker for `sam build
  --use-container`. Use current SAM CLI with Python 3.12 support.
- A deployment profile allowed to manage CloudFormation, API Gateway, Lambda,
  DynamoDB, CloudWatch Logs, the deployment S3 bucket, and the function IAM role.
- A separate runtime profile needs only the two `execute-api:Invoke` resources
  printed by the stack. It does not need direct DynamoDB or deployment permissions.
- Prefer temporary AWS credentials (for example IAM Identity Center/SSO). Never
  place credentials in source files or in the session JSON.

## Deploy (PowerShell, from the gymbro folder)

```powershell
aws configure sso --profile gymbro-deploy
aws sso login --profile gymbro-deploy
aws sts get-caller-identity --profile gymbro-deploy
sam validate --lint --template-file aws/template.yaml --region us-east-1
sam build --use-container --template-file aws/template.yaml
sam deploy --guided --profile gymbro-deploy --region us-east-1
```

Choose stack name `gymbro-sessions`; allow SAM to create its function role when
prompted (CAPABILITY_IAM), and review/confirm its change set. No secret parameters
are required. The packaged Lambda contains only `aws/src/`; no video, pose models,
virtual environment, or local session files are included. Boto3 is supplied by the
Python Lambda runtime. Keep region consistent in subsequent commands. Replace
`us-east-1` with your chosen region if needed.

```powershell
aws cloudformation describe-stacks --stack-name gymbro-sessions --profile gymbro-deploy --region us-east-1 --query "Stacks[0].Outputs" --output table
```

Outputs: `ApiUrl`, `SessionsTable`, `UploadInvokeArn`, `ReadInvokeArn`. Save them.
Give the runtime IAM identity a policy with `Effect: Allow`,
`Action: execute-api:Invoke`, and `Resource` set to the two exact output ARNs:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "execute-api:Invoke",
    "Resource": ["PASTE_UploadInvokeArn", "PASTE_ReadInvokeArn"]
  }]
}
```

Attach this through your account's IAM/SSO permission management. API Gateway uses
AWS_IAM authorization for both methods, with Lambda resource-based invocation
permissions generated by SAM (`InvokeRole: NONE`). Unsigned calls must get 403.
This is a single-operator demo: all identities granted these ARNs share the session
store. There is no per-user tenancy or public browsing/list endpoint.

## Configure the local app

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-aws.txt
$env:AWS_PROFILE = 'gymbro-runtime'
aws sso login --profile gymbro-runtime
$env:GYMBRO_API_URL = 'https://YOUR_API_ID.execute-api.us-east-1.amazonaws.com/Prod'
# Optional; otherwise JSON goes to gymbro/sessions:
$env:GYMBRO_SESSIONS_DIR = "$PWD/sessions"
.\.venv\Scripts\python.exe app.py
```

Create/configure the runtime profile first (e.g. `aws configure sso`). For other
credential sources the client uses Boto3's normal credential chain, including
`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN`. The signing
region comes from the API URL, not the computer timezone. Only the generated HTTPS
execute-api URL is supported. No custom domains or redirect following.

On exit, the app prints the saved JSON path and upload result. No network calls are
made during the workout. Upload runs in a separate subprocess capped at 15 seconds;
HTTP requests time out after 5 seconds. Failure leaves the JSON intact. There is
no automatic background retry service.

Disable AWS without uninstalling anything:

```powershell
Remove-Item Env:GYMBRO_API_URL -ErrorAction SilentlyContinue
```

## Cloud round-trip check (required after deployment)

Use the exact JSON path printed after your workout:

```powershell
$sessionFile = 'C:\path\to\sessions\SESSION_UUID.json'
$sessionId = (Get-Content -Raw -LiteralPath $sessionFile | ConvertFrom-Json).session_id
.\.venv\Scripts\python.exe aws_client.py upload $sessionFile
.\.venv\Scripts\python.exe aws_client.py get $sessionId
.\.venv\Scripts\python.exe aws_client.py upload $sessionFile
```

The first POST returns `stored: true`; a retry returns `duplicate: true`. GET must
return the same rep count, per-rep results and form totals as your JSON. Identical
retries are safe even when a previous response timed out after DynamoDB committed.
Different content under the same ID returns 409 and does not overwrite it.

Check an unsigned request is rejected:

```powershell
curl.exe -i "$env:GYMBRO_API_URL/sessions/$sessionId"
```

Expected: HTTP 403. Verify the row in the DynamoDB console using the `SessionsTable`
output. Save the deployment outputs, signed POST/GET results and a console screenshot
as evidence of actual AWS execution for the submission. A template or local mock
test alone is not that evidence; competition acceptance still depends on its rules.

## API and failure behavior

| Request | Result |
| --- | --- |
| POST `/sessions` with schema-v1 JSON | 201 new; 200 identical retry |
| GET `/sessions/{session_id}` | 200 summary; 404 unknown ID |
| Invalid JSON/fields/UUID/totals | 400 |
| Oversized body | 413 (or 400 if the parsed JSON exceeds the schema limit) |
| Same ID, different summary | 409 |
| Storage failure | 503; retry the same local JSON |
| No/expired credentials or no invoke permission | API Gateway 403 |

Maximum API summary: 128,000 bytes, 1,000 completed reps, schema version 1.
Local files are kept even if they exceed the API limit. Summary timestamps include
UTC timezone; session duration is elapsed wall-clock time. Per-rep timings are
relative to video source time or camera monotonic time and need not equal wall time.

403: check AWS profile login, exact ApiUrl/stage, system clock, and invoke policy.
503: check `/aws/lambda/<StoreFunction physical name>` CloudWatch logs and the
function table permission/environment. Do not disable IAM authorization to debug.
Missing optional Boto3 package: install `requirements-aws.txt`. Local workouts and
JSON require none of the AWS packages.

## Tests and cleanup

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
sam validate --lint --template-file aws/template.yaml --region us-east-1
```

AWS unit tests use mocked storage/transport; they do not create billable resources.
Throttling is set to 2 requests/second with burst 5. The table uses on-demand billing;
logs expire after 7 days. These are not hard spending caps.

When finished, `sam delete --stack-name gymbro-sessions --profile gymbro-deploy
--region us-east-1` removes the API/function/stack resources. **The table is retained**
to protect workout history, so it may continue incurring storage charges. Export
needed records, then explicitly delete that retained table in the AWS console if
you want to remove the data. Review any SAM deployment bucket artifacts separately.
